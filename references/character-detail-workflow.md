# 人物细节参考与制作

把一张人物参考展开成能指导建模的视觉资料，并用局部实物结果反复对照。按任务读 [人物生图提示词](character-detail-prompts.md)；导入技术与运行检查复用 [资产桥接](asset-bridge.md) 和 [运行验收](runtime-checks.md)。

阶段顺序、产物展示和等待点遵循 [执行阶段与用户确认](production-checkpoints.md)。技术自检通过与用户确认分开记录，不能把本文件的“通过”自动理解为用户认可。

## 1. 从参考中提取稳定的设定

查看用户实际人物图。有本地路径先打开图片；帖子截图、文字说明或工具安装示意不等于人物参考。没有人物图而有完整设计描述时可先生成设计母版；两者都不足时只推进流程设计，向用户获取人物参考或描述。

确认本次是参考图包、人物模型、已有角色修复还是完整游戏，保持用户范围。沿用指定的风格、用途、角色身份、服装和材质，不自动写实化。已有模型时先看实际问题和目标使用距离，判断需要补哪些图。

用简短记录固定人物比例、脸型、发型轮廓、发色、服装层次、配色、饰品数量和佩戴侧。左右一律以角色自身为基准，避免正面画面左右造成镜像错误。

对细节标记来源：**原图可见 / 用户已给定 / 为完成设计而补充 / 尚不确定**。被遮挡的背面、口腔、衣服内层和扣件不能被称为从单张图准确还原；采用符合现有设计的简洁补充并记录。身份或设计有实质冲突时先解决冲突再制作下游图。

## 2. 建立母版，再展开局部

开始调用前读取 [工具选择与调用](tool-routing.md)，分别确认生图、3D 生成与 Blender 控制能力；不能用“已安装 MCP”代替这三项检查。

优先用当前环境的 imagegen 生图能力，按实际工具说明传入参考图。每个输入写明用途：原图控制身份与风格，母版控制比例与背侧设计，局部原图控制细节，已有模型截图提供当前问题。

保持参考的生成请求和局部修图使用正确的工具输入；不要只写一段描述让模型凭记忆重画。需要的参考超出工具容量时保留关键原图与母版，将其余约束写清，不能声称工具看到了没有传入的图片。内置生图可用时不因多图任务擅自转用付费 CLI/API。

1. **统一母版**：整身通常为正面、严格侧面、背面，中性站姿、同一比例、相近正交表达、中性灯光与干净背景。左右不对称时补另一侧；必要时另加四分之三视图检查体积。
2. **头部母版**：人物近景重要时独立生成头部正面、侧面、四分之三图，保持眼线、鼻底、嘴和耳的位置关系。不能将全身小头像放大视为五官细节完成。
3. **局部图**：仅围绕高价值部位、已观察到的失败或必要的制作依赖生成。每个部位一张有足够分辨率的独立图，不把所有细节塞进一张密集大海报。

“三视图”是表达方式，不是每种部位必须凑三张：耳朵可能需要外侧与后侧，饰品需要连接面，头发需要顶视与后视，嘴部需要闭合和张开的状态。按建模问题选能消除歧义的视角。

生成图的近似正交表达并非摄影测量或严格 CAD 投影。检查关键高度与轮廓能否对应；不一致时局部修正，不用看似精确的尺寸标注掩盖矛盾。真实尺度由用户约定或模型测量确定。

## 3. 每类细节图应回答什么

| 部位 | 参考图需要表达 | 对应制作决策 |
| --- | --- | --- |
| 脸与五官 | 头颅和下颌轮廓、眼眶/眼睑厚度、鼻梁/鼻翼、唇部体积、耳廓与耳根；按需局部放大 | 脸部体块、眼口拓扑、独立眼球及口腔，而非把五官全画进平面贴图 |
| 头发 | 发际线、分缝、发根到发梢流向、主发束与次发束、前后层次、截面体积、直卷与光泽 | 选择曲线、成束网格或发片；先定大形和走向，再做发丝/透明贴图 |
| 衣服 | 内外层、领口袖口、接缝/缝线、扣件、下摆、静止褶皱及面料厚薄 | 分层建模、UV 分区、材质；褶皱应随姿态和材质变化，不全固化为几何 |
| 饰品与装备 | 正/侧/背或底面、厚度、连接点、佩戴方向、遮挡关系、材质细节 | 独立对象、附着位置与旋转轴；不能只得到悬空的正面花纹 |
| 手脚 | 指掌比例、指节/指缝、手背/手掌、鞋底与脚踝连接 | 结构修整、关节权重、接触与穿插检查 |
| 表面与材质 | 无强光影的颜色细节、纹理方向与尺度、皮肤/布料/金属/皮革差异 | 颜色来源、材质分区和 UV/投射计划；不把参考图直接当最终 PBR 贴图 |
| 关节与骨架 | 身体比例、肩肘腕/髋膝踝位置、眼球与下颌控制、发束和衣摆的运动需求 | 在实际网格建立骨架层级、轴向与权重，用姿态验证 |

## 4. 先过一致性检查，再把图交给建模

每张局部图都对照原始参考、当前母版和相邻部位，不能只看上一张生成结果，以免多轮后换了一个角色。

- 面部比例、年龄感和脸型是否保持；不同视角的眼耳位置、鼻下颌轮廓是否能解释成同一个头部。
- 发际线、发缝、束数与主轮廓是否一致；刘海是否与眼睛、耳饰的空间关系冲突。
- 衣领、袖口、腰线、内外层在正侧背是否连续；饰品数量、形状和角色左右是否一致。
- 不同部位的材质、颜色、厚度和尺度是否一致；没有凭空新增结构或把隐藏侧当成已知。

单项不符优先修该图，保留通过的图。若母版必须改动，标记依赖它的局部图待复查，不自动全部重生成。按照用户预算和当前模型瓶颈安排生图，资料足够指导下一步即开始建模，不无限收集细节。

开始下游前检查当前协作模式要求的确认是否已完成；默认局部图按批展示后自动继续，母版和头肩小样等关键确认点等待用户或复用其明确授权。

项目内保存真实输出路径和简短索引，示例：

| 部位 ID | 图/版本 | 来自哪张原图与母版 | 已知/补充设计 | 状态 | 对应对象/材质与下一步 |
| --- | --- | --- | --- | --- | --- |
| hair-main | 实际文件路径 | 原图、母版实际路径 | 背面发束为补充设计 | 通过/待修/待复查 | 对象尚未建立；先匹配发型轮廓 |

记录生成提示词和关键修正即可，不建立复杂资产数据库。图像自带的文字标签不可靠时用旁边的索引说明，不依赖乱码尺寸和解剖名称。

## 5. 把细节图落实为几何、贴图和绑定

**先验证头肩小样。** 按需求使用可靠人物底模、专门 3D 生成工具或 Blender 制作；母版和部位图提供约束，不假定生图本身会输出合格 3D。用户禁止外部服务/资产时遵守限制；没有合适工具时披露模型未完成，不将占位几何称为精细人物。

制作时将通过的部位图对应到具体对象与材质，固定模型相机分别渲染正/侧/斜面，对照相关参考。全身场景漂亮不能抵消脸部失败。

执行 [多视角建模对照](character-visual-comparison.md)：imagegen 提供固定目标，Blender 输出真实模型的同视角结果，Codex 看两者并定位偏差。不能用 imagegen 美化后的模型截图冒充实际建模进展。

按以下顺序诊断，避免贴图与灯光掩盖形体：

1. **灰模**：脸型、五官体块、发束体积、衣层、饰品厚度与连接关系。
2. **UV 与颜色**：棋盘格检查拉伸/接缝；无光照颜色检查是否画入错误眼口、阴影和高光。
3. **完整材质**：在中性光下看皮肤、眼睛、头发、衣物，再看目标场景效果。风格化与写实分别采用合适标准。
4. **表情与动作**：闭眼、张嘴、眨眼叠加口型、抬肩屈肘、蹲下与需要的运动；在目标引擎重复检查。

**细节图不等于可用贴图。** 图像需经模型 UV 对齐或投射，修接缝并按需求烘焙；数据贴图的法线空间、色彩空间和通道依据真实引擎合同。修颜色时尽量固定几何和 UV。没有对应 UV 和实际贴图检查时，只交付“材质参考”。

**骨架示意不等于绑定数据。** 用户所说的骨骼细节，通常应落实为关节位置、骨架层级、控制和变形需求。以实际模型与可信的人体/绑定知识设计，并记录哪些是推断；可用生图辅助表达外观结构，但不从生成的骨头图直接复制坐标、宣称解剖准确，或把画出的网格线称为真实拓扑。

骨架、轴向和层级最好直接在 Blender 或确定性示意图中表达。表情所需的眼球、眼睑、口腔应先具备，待拓扑稳定再做形状键；独立生成的多个表情模型不天然具有可混合的顶点对应。模型交换式表情只有满足用户用途时才采用，并披露连续性限制。

## 6. 按请求范围交付

- **参考图包**：母版、需要的局部图、实际文件路径/提示词、一致性检查结果、补充设计项。明确尚未验证模型、UV、骨架或性能。
- **角色制作/修复**：除参考图外，提供实际模型与贴图，展示灰模/完整材质近景和适用的变形检查结果；未验证项单列。
- **完整游戏**：角色通过专项检查后继续主技能的玩法和运行验收。

此模块是基于用户提出的分层细节生图方向，以及此前人物案例调研整理的执行方案。流程规则和结构校验不构成精细人物质量保证；首次真实角色任务需要验证跨图一致性与建模结果。
