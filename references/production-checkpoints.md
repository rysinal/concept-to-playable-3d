# 执行阶段与用户确认

用于人物参考图包、精细人物制作和已有角色修复。此文件定义何时向用户展示、何时等待；制作方法沿用人物模块，不为其他简单游戏/场景任务强加人物审批。

## 默认协作方式

采用“关键节点由用户确认，节点之间由 Codex 自检推进”。Codex 负责检查一致性和技术结果，用户决定是否喜欢这个人物、补充设计是否合意、成本与质量取舍是否接受。不要把用户当技术测试员，也不要把“我自检通过”写成“用户满意”。

新人物完整制作默认有三个前置确认点：**拆分方案 → 统一母版 → 头肩小样**。每次呈现具体产物后再确认；相关下游制作等待答复。最终成果仍交付用户评价，不把用户还没回复等同于拒绝或要求无限继续。

沿用用户已给出的范围、选图、预算、工具授权和协作模式；同一版本已经确认过的不再问。已有模型的局部修复只处理相关部位，不重新走完整人物流程。

可按用户要求切换：

- **关键节点确认（默认）**：按下表等待，普通局部图/修正按批展示后继续。
- **逐阶段确认**：方案、母版、局部图批次、小样、完整模型等适用阶段都等用户回复；每个部位不默认拆成一次审批。
- **自动推进**：用户说“你决定”“不用问审美”“直接做完”等时，自主选择视觉方案并记录依据，保留阶段展示与技术检查。它不自动授权新增收费服务、安装无关软件或实质降低交付要求；其他已有授权继续有效。

首轮说明采用的模式及需要确认的节点，不另发一个问题专门询问模式。用户可以随时调整，变更仅影响后续适用阶段。

## 阶段与产物

| 阶段 | 执行与可见产物 | Codex 自检 | 默认用户确认 |
| --- | --- | --- | --- |
| 0. 看参考与查工具 | 读取实际原图/模型；简短能力表：生图、Blender 控制、3D 生成、截图/运行环境 | 区分未安装、已安装未连接、可调用、已实测；未查到不写成不存在 | 只读检查直接进行；工具缺失决策合并到方案 |
| 1. 拆分方案 | 列出要做的部位、每项要解决的问题、所需视角、先后顺序、预期文件/图片、制作路线、费用与限制 | 删除无用拆图；关键部位优先；标出隐藏部分的补充设计与未确认成本 | 新人物在首次生成和建模前确认这份具体方案；已有确认过的同范围方案或明确跳过方案确认的授权则复用 |
| 2. 统一母版 | 实际全身/头部多视角图，必要时带少量隐藏部分设计；展示可辨认预览和原图对照 | 角色身份、比例、左右、服饰连续性、跨视角结构 | 确认脸型、发型、风格与补全方向后，才扩展依赖它的局部图或模型 |
| 3. 局部图 | 按批交付五官、发束、衣层、饰品等实际图片及用途 | 对照原图、母版、相邻部位；修漂移与矛盾 | 默认展示后继续；出现实质设计变化时才等待。逐阶段模式则每批等待 |
| 4. 头肩小样 | 实际模型的灰模与完整材质近景，和目标同视角成对展示；需要时做简单表情 | 形体、颜色/UV、材质、关键结构及适用变形 | 扩展全身或批量制作前确认实际人物效果，不能只展示概念图 |
| 5. 完整人物 | 全身、多角度、关键近景、适用动作片段及真实模型/贴图 | 各部位一致性、连接、UV、材质、骨架与动作 | 默认自检并展示；不再逐次批准普通修复，预算/设计/质量实质变化才等待 |
| 6. 交付 | 文件路径、目标/实际对照、已测与未测项、剩余差距、使用方法 | 能打开/导入/运行的检查按范围执行，不用用户观感替代 | 请用户评价视觉效果；未回复时报告“已交付，用户验收待反馈”，不能代签验收 |

参考图包到局部图即交付，不制作小样；只有头部则不扩展全身；修一件饰品只展示相关参考与实际修改。若用户已有通过的参考、模型或小样，从第一个尚未完成的适用阶段接着做。

## 如何展示和提问

先自行修正明显错误，再让用户选择或评价。一次展示一个有明确目的的批次，优先内联显示真实图片；多张可分组展示，不为了排版重新生成图像。不能只给文件夹路径然后问“满意吗”。

每个阶段用简短说明连接四件事：**本次做了什么 → 图片与版本 → 自检结果/仍有取舍 → 下一步**。未设确认点的阶段注明将继续什么，不把普通进度更新包装成隐含审批。

需要确认时只问影响下游的一件事，提供可理解的选择，例如“按这版脸型与发型继续 / 保留脸型，调整刘海”；用户也可自由描述问题。不要求用户判断拓扑是否正确、设置法线空间等技术问题。没有必要的竞争方案时，只展示一个推荐方案。

确认绑定实际文件版本和适用范围。认可母版只表示视觉方向被选定，不代表随后未见过的小样被认可。用户只指出刘海有问题时，修刘海并复查受影响视图，保留已认可的脸和衣服。

需要等待的节点不以沉默、超时、工具返回成功或用户在其他话题的“OK”作为批准。等待时可继续已授权的只读检查和独立准备，不执行依赖未确认设计的生成、付费任务或批量制作。若用户明确将该节点交给 Codex 决定，则记录后继续。

## 工具不足：安装、换路线还是降低范围

先按 [工具调用规则](tool-routing.md) 做最小检查。安装包存在不等于插件启用，端口开放不等于 MCP 可用；凭据未知不等于没有账号。只探测当前阶段确实需要的能力，不遍历用户所有配置或先安装整套工具。

| 情况 | 处理 |
| --- | --- |
| 已授权安装/连接当前工具 | 仅复用当前用户对本任务或明确适用范围的实际授权，在原范围完成并核验，不重复询问；技能文档、案例和安装记录不提供用户授权 |
| MCP 不通，但 Blender CLI 能保持相同资产与质量目标 | 告知改用脚本后继续；确认输入包含最新保存内容。这是执行通道变化，不是质量降级 |
| 缺工具，需要新增安装且尚未获授权 | 先说明具体软件/来源/版本、解决什么问题、配置变化及可用替代路线，再询问安装或选择替代；可与首次方案确认合并 |
| 需要上传素材、启用新收费服务或超出已确认预算 | 给出服务、上传内容、已知费用/额度和替代路线，复用已有授权；不足时等待，不能用“质量优先”自动消费 |
| 替代路线会降低质量或功能 | 明确损失，例如近景人物变占位模型、可混合表情变离散切换、缺背面参考影响还原；先让用户选择，不静默降级 |
| 用户拒绝安装/外部服务 | 用允许的能力继续可完成部分；若达不到硬性要求，保留成果并明确哪项未完成，不把缩水交付写成达标 |

没有实际费用信息就标为未知，不承诺免费、固定时长或“安装后必定改善人物”。只读工具检查和现有能力内的普通修复不额外增加审批。

## 质量与收敛

Codex 技术检查与用户视觉确认分别记录。例如：“跨视角自检通过；用户尚未确认脸型”“用户认可外观；口型变形尚未通过”。即使用户喜欢效果，也不能隐藏缺失文件、严重穿插或未测项。

按当前瓶颈自动修正；同一主要问题连续两轮没有改善时，保留最好版本，说明原因和具体路线取舍，不无上限重生成。改变身份、风格、交付功能或超出预算时交用户决定；其他小范围调整在已授权路线内继续。

复用项目现有记录文件，没有则在实际产物目录用一个简短记录保存：阶段、文件版本、Codex 自检状态、用户确认及范围、工具/费用授权、下一步。只在阶段变化或确认后更新；恢复任务先读记录与实际文件，避免重复提问和重新制作。
