# Blender 到游戏运行时

按目标工程的 Blender/引擎版本核对 API 和导入合同；以下是检查项，不是可直接执行的 MCP 参数。

## 工作方式

工具选择、两种 MCP 的区别、安装示例、调用顺序与 CLI 路线见 [工具选择与调用](tool-routing.md)。

- 从本轮工具列表确认真实 MCP 方法与参数。若用本地 Blender Python，使用当前版本文档；不要臆造 `blender.*` 工具。
- 先读取当前场景和文件路径。修改前保存有名称的副本；将新资产放入明确命名的集合，不全选删除用户场景。
- 按主体形体、材质、导出拆分有副作用的操作。MCP 超时后先查询对象/文件是否已经生成，再决定是否重试，避免重复网格。
- 保存可编辑 `.blend`；导出文件是运行时资产，不替代源工程。

## 代表性资产的导入合同

| 检查项 | 需要验证的结果 |
| --- | --- |
| 尺度、坐标轴、原点 | 在目标引擎中方向和尺寸正确，旋转轴/落脚点合理 |
| 形体 | 在实际游戏距离下轮廓可辨；有需要时检查背面和近景 |
| 网格 | 记录导出后的三角形、材质批次；不以 Blender 对象数推断 draw calls |
| UV 与纹理 | 密度、平铺接缝、方向和材质通道正确，缺失贴图可检测 |
| 材质 | 导入后与参考接近；程序节点和离线渲染效果未必可直接导出 |
| 动画（需要时） | 骨架、动作、轴向和循环在引擎内实际播放正确 |
| 碰撞（需要时） | 使用适合玩法的碰撞形体；与视觉表面相符 |
| 文件依赖 | 导出包包含或正确引用纹理；干净启动无丢失资源 |

Three.js 通常使用 GLB/glTF；其他引擎沿用已验证的格式。Blender 中好看的程序节点材质需要转换为可支持的材质、烘焙纹理或在引擎重建着色器。先导出一件再看真实结果。

## 生图纹理的使用边界

- 区分场景概念图、无光照 base color、贴花、UI PNG 和环境图。不能把带透视、阴影和高光的整张概念图随意贴上网格。
- 需要平铺时请求并检查无缝接边；需要透明背景时检查实际 alpha，棋盘格图案不等于透明。
- 法线、粗糙度、金属度等数据贴图要检查空间、范围和引擎约定。生图输出即使名为 normal map，也不能直接认定为正确 PBR 数据；可靠场景优先烘焙或计算后验证。
- 控制材质槽、重复纹理和分辨率，按实际画面占比安排预算；不把某个案例的 1 万面变成所有资产的统一标准。
- 用户允许外部素材时记录来源及适用许可；禁止外部素材时采用自制/生成/程序化路线。未授权时不上传用户私有模型到外部生成服务。
