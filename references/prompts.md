# 可调整的提示词

将方括号替换成实际需求。以下用于组织请求，不固定模型、工具名或画风。

## 从想法开始

```text
使用 $concept-to-playable-3d 做一个 [玩法] 的小型 3D 游戏。
画风：[参考图/描述]；相机：[视角]；目标：[平台/设备/分辨率/FPS]。
核心循环：[动作 → 反馈 → 目标/失败/重试]。
沿用当前工程；没有工程时选择适合交付的平台方案。
先生成可实现的引擎内目标画面，用 Blender 或程序化方式制作合适的资产，
完成一个可玩切片，再拿真实截图对照迭代。记录真实性能与未完成项。
素材限制：[如只用自制和生成素材]；预算：[如本轮 45 分钟]。
```

## 生图建立目标

```text
生成 [画风] 的实时 3D 游戏引擎内画面参考，面向 [平台]。
保持 [相机角度/FOV/角色占比/画幅]，主体为 [主体]。
布局：[前景]、[中景玩法区域]、[远景地标]；通路与互动目标清晰可读。
光照：[主光/补光/阴影/空气感]；色板：[主色和强调色]。
重点表现 [两三种主要材质和主体结构]，背景细节有层次。
不要海报构图、摄影噪点、无意义小物堆叠或无法实现的几何。
保留指定风格，不因为高品质就改成写实。没有要求时不加文字 HUD。
```

## 从现有截图提升

```text
以提供的真实游戏截图为基础生成改进目标。
保留相机、主体身份、关卡结构、可行走区域和指定画风。
提升 [实际诊断出的光照/材质/层次/轮廓]，避免增加改变玩法的物体。
结果应当能指导这个工程的下一轮修改；不要另画一个无关场景。
```

## 主体建模参考

精细人物按 [人物细节生图模板](character-detail-prompts.md) 建立母版与局部参考；以下通用模板适用于较简单的主体。

```text
基于选中的主体图制作前、侧、后和四分之三视角参考。
各视角保持同一物体、相同结构比例、配色和材质；中性背景与清楚轮廓。
显示 [最重要的结构特征]。若原图不能确定背面，采用简洁设计并标注为推断。
这是建模参考，不声称它具有真实测量精度。
```

## 截图评审

```text
对照目标图与当前实机图，遵守用户画风和玩法要求。
先检查上轮问题是否已解决，再按布局、光色、表面、细节排序，
给出当前最影响结果的最多三个差距：对象、可见现象、可执行修改、复查方法。
不要把增加粒子或 bloom 当成所有问题的答案，也不要强制写实化。
只根据提供的证据判断；图片无法证明的帧率、操作和动态稳定性标为未验证。
```
